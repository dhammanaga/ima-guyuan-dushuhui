## 二、朗读正文与字数上限（硬约束）

> ⚠️ **2026-10-12 尊者裁定：本节已按新口径重写，旧口径（4周版8000/8周版6000 总量）作废。**

### 2.1 唯一算法：时长 × 语速 = 朗读字数

**语速口径：中等偏慢朗读 = 180 字/分钟**（受众为中老年、中年女性；常规朗读 250–300 字/分钟不算）。

| 版本 | 共读环节时长 | **该环节朗读字数上限** | 判定方式 |
|:--|:--:|--:|:--|
| **4 周版** | 共读原文1 = **20 分钟** | **≤ 3600 字** | **逐段各自独立判定**，不合并 |
| **4 周版** | 共读原文2 = **20 分钟** | **≤ 3600 字** | **逐段各自独立判定**，不合并 |
| **8 周版** | 共读 = **25 分钟** | **≤ 4500 字** | 单段判定 |

推导：20 × 180 = 3600；25 × 180 = 4500。

**要点**：
- **只计算"要念出来"的字数**。不念的（速览表、信息卡、讨论题、特别提醒、延伸阅读、主持人操作行、课前准备清单）**一律不算**。
- 4 周版是**两段共读**，两段**各自 ≤3600**，**不是**两段相加再比。
- 8 周版只有一段，≤4500。

### 2.2 「朗读正文」判定范围（怎么数）

**＝ 仅 `## 📖 共读原文N` 整节内的可朗读文字。**

| 计入 | 不计入 |
|:--|:--|
| 材料正文段落（原文照录） | 整份文件总字符数（含速览表、信息卡、讨论题、特别提醒、延伸阅读） |
| `**一、xxx**` / `**【◈扩展…】**` 等段标题行本身 | `### 原文材料X：…` 材料标题行 |
| | `- **文件**：《…》` 行 |
| | `> ⚠️ 主持人操作：` 行、`> 主持人：` 行 |
| | `**主持人课前准备…**` 及其下 1./2./3. 编号清单（备料，不朗读） |
| | `---` 分隔行 |

### 2.3 ★核心 / ◈扩展 与扩展段上限（2026-10-13 尊者令：扩展字数不限）

- **★核心＝要念的**，量须控制在 2.1 的上限内。
- **◈扩展＝时间富余才加读的**：**字数不受限制**。
  > 尊者原话（2026-10-13）：「**放宽字数限制，拓展内容字数不受限制。**」
  >
  > 旧令（2026-10-12「扩展内容也不要多，不要超过5分钟字数」＝≤900 字）**已废止**。
- **判定变化**：`count_spoken.py` **只判全段 ≤3600**（8 周版 ≤4500），
  **不再对 ◈ 扩展段单独判超**，仅统计并显示其字数（形如 `扩展 1520(不限)`）。
- **仍须遵守**：扩展段内容**不得跑题、不得重复**（8.6 成因③），
  仍应来自本周知识地图的释义落点，**不得为凑量而灌水**。

### 2.4 双向字数令（尊者）

> 「字数限制要遵守，不足要补足（要符合知识框架和要点，不跑题不重复），超过要减少（不丢要点）。材料来源于知识库，也可以直接用原文全集里的内容。」

- **不足 = 缺口，必须补**：优先补「讲稿正文已引用、但没落到原文」的悬空段落。
- **补写来源优先级**：仓库内 `原文全集.md` > IMA 知识库。
- ⚠️ 补进来的正文仍受 ★/◈ 分级约束，**别把 ◈ 全提成 ★**。
- ⚠️ 补原文必须剔掉原文自带的层级标题行 `^#{1,6}\s`（会与讲稿编号形成「一、二、一」跳号并造成内容错位）。

### 2.5 超限处置（顺序不可颠倒）

1. **先删 / 压 ◈扩展段落**（整段或其中次要段）；
2. 再对 **★核心段落做句内压缩**（去口头填充、去重复例证）；
3. **不得删掉当周课题的任何知识要点**——★核心段的知识要点、术语、数字、经文引文一个不许丢。
4. 删掉的整段要在该材料「⚠️主持人操作」行注明去向（例："整段不收入本周正文，见延伸阅读"）。

### 2.7 其他保留约束

- **只保留可朗读的正文**；材料信息一律只写 `- **文件**：《…》` 一行。
- 保留 `**★核心段落**` / `**◈扩展段落**` 小标题与「一、二、三」编号小标题，维持次第。

## 三·七、回向词与收尾（🚫 绝对不可改动·2026-10-12 尊者令）

### 三·七·1 回向词：**任何时候、任何场合都不可以改**

**唯一版本（逐字照录，一字不改、一句不删、不另写、不改标点）**：

```
愿我此功德，导向诸漏尽！
愿我此功德，为证涅槃缘！
我此功德分，回向诸有情！
愿彼等一切，同得功德分！
```

- **格式**：四句各占一行，`>` 引用块内，行尾两个空格（Markdown 换行）；四句用**加粗**。
- **出处**：《清净业障摄颂》回向偈。
- 🚫 **禁止**：
  - 改字（漏尽／涅槃／有情／功德分…一个字都不能动）
  - 改标点（必须用中文全角 `！`，不得改成 `.`／`。`／无标点）
  - 增删句子、调整顺序、另写回向文
  - 改写为「愿以此功德…」等自造版本（**2026-10-12 全库查出 9 份文件有自造回向文，须一律换回标准四句**）
  - 在回向词前后加「照读不省」「约 2 分钟」以外的自创指示语
- 主持人**领读，全体合掌齐诵，照读不省**。散会前念完，不再另行替代。

### 三·七·2 收尾环节：**只设一个，不拆「收尾一 / 收尾二」**

- 4 周版 9 环节结构里，**收尾与回向是单一环节**（15 min），**不得拆成「收尾一」「收尾二」或更多子节**。
- 内部顺序（固定）：
  1. **总结引导**（前半：本周正文义理收拢）
  2. **本周作业细则**（向成员逐条确认，不与「作业再确认」重复宣读）
  3. **逐人回扣**／**本课后半段衔接**（按周次有无取舍）
  4. **下周预告**（约 3 min）
  5. **回向词**（全篇唯一一份，位于收尾末尾）
- 🚫 **同一份作业不许宣读两遍**——「本周作业细则」出现后，后面只能写「与前面同，不再重复宣读；请成员确认已在记录表上」。

- **自检**：`grep -c "愿彼等一切"` 必须 == 1；`grep -cE "^### 收尾(一|二)"` 必须 == 0。

## 八、交付前三维度验收（覆盖度·表述完整度）★必做（2026-10-13 尊者令）

> 前面各节管「怎么写」，本节管「写完凭什么说它够」。
> **光跑 `count_spoken.py` 拿到 ✓ 合规，不等于交付合格**——它只查结构与字数，查不出漏了什么、讲清了没有。
> 本节是交付前的**最后一关**，适用于每一周、每一个系列。

### 8.1 三个维度，缺一不可

| 维度 | 回答的问题 | 判定物 | 不合格的后果 |
|:--|:--|:--|:--|
| **① 覆盖度** | 知识地图里的知识点，文档**有没有**？ | 覆盖矩阵（原子级） | 漏讲 |
| **② 篇幅配比** | 该说500 字的知识点，**给了多少**？ | 散点图（复杂度 × 实际字数） | 欠写 / 超冗 |
| **③ 要素槽位** | 提到了，**讲清楚了没有**？ | 槽位检查表 | 讲了等于没讲 |

⚠️ **三维度必须交叉验证，单维度只能得半截结论。**
典型：本库第1周实测「篇幅超标 888 字」与「F4 观察方法整块缺失」看着是两类问题，
实际**同一病因**——素材材料③ 整节 664 字未纳入文档。补这一节，两个问题一起解决。
**只看任一维度都会误判方向。**

### 8.2 ★覆盖矩阵（覆盖度）

#### 8.2.1 拆到原子级，不许按「框架条目 + 要点」粗判

- **一条框架要点实际含 4–8 个原子知识点**。拆法：一条要点里每一个可独立提问的判断、每一个术语的释义、每一条引文，每条单列，编号 `K01…Kn`。
- **实测教训（第1周）**：按「5 框架 + 7 要点」粗判报「12/12 = 100% 覆盖」；按原子级 35 点复检，真实值是 **24/35 = 68.6%**。同一天、同一个文件，两个数字差 31 个百分点。
- **粗颗粒度是系统性高估**，不是笔误——因为命中一条即整条判「完整」，漏的4–8 个原子点全被这一条掩盖。

#### 8.2.2 ★判定域＝讲解本体，导航层不计入

**判定域 = 共读原文1 + 共读原文2（讲解本体）。**

以下**一律不计入**「已讲解」：

| 不计入的层 | 为什么|
|:--|:--|
| `## 🗺 本周知识地图` | 只提示「有」，不构成「讲清楚了」。含树形地图与要点清单，**术语命中率虚高** |
| `## 📋 本周信息卡` | 导航 |
| `## 📖 延伸阅读` | 只登记书名，不讲内容 |
| 任何 **目录/要点速览** | 同上 |

**实测教训（第1周）**：用 `s.count(kw)` 扫**全文件**，把知识地图节与延伸阅读的**导航性提及**当成了讲解。
证据：`藤`／`三处削`／`八处`／`四圣谛` 在**讲解本体 0 命中**，只存在于导航层 → 被误判为「已覆盖」。
**这是比颗粒度粗更隐蔽的错误，因为它看起来有数据支撑。**

#### 8.2.3 ⚠️ 关键词计数 0 命中 ≠ 缺失（必须回原文核对）

**这是硬性要求，不是建议。**

关键词检索 0 命中时，**必须回原文逐条人工核对异写**，才可判为缺失。
实测反例：`因漏集起故` 检索 **0 命中**，回原文一核——引文好好地在，文档用了巴利术语方括号插入的异写形式 `因漏[āsava]集起故`。
**若当时直接采信计数结果，会凭空造出一个不存在的缺口，并据此写进补漏清单。**

合法的异写形态（检索时须一并纳入）：

- 巴利/梵语术语方括号插入：`漏[āsava]`、`无明[aññā]`
- 新旧译并列：一段内容在文档中以「新译：…」「原译：…」两种形态并存
- 转写重复：同段内容以不同标点重复出现（`(作为先首)` vs `[作为先首]`）

#### 8.2.4 判定符号（四档）

| 符号 | 判定 | 含义 |
|:-:|:--|:--|
| **●** | 完整清晰 | 讲解本体中有独立落点，术语准确，可直接朗读 |
| **◐** | 完整但晦涩 | 提到了但用了省略/生僻表述，学员听不懂 |
| **○** | 部分覆盖 | 素材散落在多处，**未串成完整判断句** |
| **✗** | 未覆盖 | 回原文核对后确认讲解本体中不存在 |

**「○」这一档最容易被漏判。** 素材里有「不知四谛」「苦谛」「无常」，但从未串成
「无明＝对真相的不知」「从四圣谛角度看问题」这样的**完整修法句**——
检索命中两个词就判「完整」是错的。**判断句/总括句是否落地，是○与●的分界。**

### 8.3 篇幅配比（该多少 vs 给了多少）

- **核心认知：字数本身不是问题，「该说 500 字的知识点只写了 30 字」才是问题。**
- 做法：**应需字数**从知识地图该分支的展开程度反推（铺得越细 → 越复杂 → 应给越多字），**实际字数**直接统计，算配比。
- 散点图三区：`欠写`（实际 ≪ 应需）／`合格带`／`冗余`（实际 ≫ 应需且已挤占他处额度）。
- ⚠️ **篇幅只是可疑信号，不是判决。** 有的知识点天生一句话就够（术语定义），有的天生需要长篇。
  **必须配8.4 的槽位表判别「虽然短但说清楚了」与「虽然短且没头绪」。**
  判据：**篇幅低但槽位齐全的，判为「通过」而不是「欠写」。**

### 8.4 要素槽位（说不清楚→ 可枚举）

一个知识点要说清楚，几乎必然包含若干固定组件。**缺组件比字数少更致命，而且完全可枚举、可半自动化检查。**

标准 6 槽：**定义 / 原理依据 / 操作步骤 / 边界条件 / 例子 / 与相近概念的区别**

检查表记「已有几 / 6」，如`3/6`、`1/6`。**补写时按槽位定位到缺哪一段，不必重写整节。**

半自动化规则（有则先粗筛，再人工确认）：

| 槽位 | 可检索的特征 |
|:--|:--|
| 操作步骤 | 有无编号步骤、有无「首先/其次/然后」 |
| 边界条件 | 有无条件状语（若…则…／除非／仅当） |
| 例子 | 有无示例标记（例/ 比如/ 譬如） |
| 概念区分 | 有无对比段（「与…不同」「勿混」）、术语辨析 |
| 原理依据 | 有无引文出处（中部·x·y、相应部·x·y） |

**⚠️ 要素槽位与篇幅交叉读，才有诊断力。** 实测（第1周）：简单知识点 5/6 达标，复杂知识点仅 1/6
→ **不是普遍性单薄，是复杂度高的知识点被系统性压缩**。这类问题人工通读最容易漏，
因为每一段单看都「像是有的」，但复杂处实际是空的。**这正是散点图必须配槽位表的原因。**

### 8.5 ⚠️ 双维度交叉：区分「短但够」与「短且不够」

| 篇幅 | 槽位 | 判定 |
|:--|:--|:--|
| 低 | 齐全 | **通过**（纯字数统计会误报成欠写） |
| 低 |残缺 | **欠写**（真问题，需补） |
| 高 | 齐全 | 通过（但检查是否挤占他处额度） |
| 高 | 残缺 | **冗余且不合格**（删重复、补要点，优先删） |

### 8.6 ★缺口按成因归类（补法完全不同）

出报告时**必须把缺口按成因分组**，因为每一类的补法、难度、成本都不一样：

| 成因类型 | 特征 | 补法 |
|:--|:--|:--|
| **① 总纲缺失** | 核心命题/总纲句在讲解本体中不存在 | **要新写**；缺它整周没有锚点 |
| **② 框架要求但内容为零** | 框架明文要求的段落，讲解本体中确实为空 | **要新写**；P0，素材若在优先照录 |
| **③ 判断句/总括句未落地** | 素材散落在多处，未串成完整句 | **只需搬运串句**；改动量最小、性价比最高，优先做 |
| **④ 素材整节未纳入** | 素材里有完整一节，文档完全没用 | 照录；须先腾字数 |

**价值**：把「11 个缺口」变成「4 种病因 + 各自处方」。**③ 类往往一次能消掉近一半缺口。**

同时看**框架条目维度的分布**——若靠前的总纲框架明显薄于靠后的细节框架，
是「**细节讲得比纲领多**」的倒挂，属结构性问题，不是随机缺漏，须整体调整而非逐点补。

### 8.7 ★字数冲突时的合法腾挪顺序（不可颠倒）

**前提**：`count_spoken.py` 判**全段上限 ≤3600**（8 周版 ≤4500）。
**◈扩展段字数已不受限制（2026-10-13 尊者令）**——扩展内容可自由增补，不必再为扩展段腾字数。

⚠️ 但**全段上限仍须遵守**：脚本报的`全段 x/3600` 是核心＋扩展之和。
**若全段超限，新增内容仍须在同段内找到合法删减位**，优先级顺序：

| 序 | 删减位| 合法性依据 | 风险 |
|:--:|:--|:--|:--|
| 1 | **转写重复段** | 去重复，不丢任何要点 | 最低，首选 |
| 2 | **原译**（若主持人操作行已授权「可只读新译、带过原译」） | 操作行已明文授权 | 低；**删前必须核实对应新译完整含关键引文** |
| 3 | **★核心句内压缩** | RULES5 2.5（去口头填充、去重复例证） | 中；**术语与数字一字不许动** |

**腾字数删什么，绝不删：**

- 🚫 术语（名色分别智·缘摄受智·六种巴利术语…）与**数字**
- 🚫 关键引文与出处（中部·1·103／相应部·2·19／purimā koṭi／pubbanta…）
- 🚫 ★核心段的照录正文要点（压无可压时，宁可整段不入正文、在操作行注明去向——RULES5 2.5 第 4 条）

**删前必做**：核实被删内容的关键引文/术语在保留部分**确实存在**，
并在报告里列出「删了什么／依据是什么／保真校验结果」。

### 8.11 ★★ 知识地图必须逐点带释义（2026-10-13 尊者令）

> **尊者原话**：「你的问题是知识地图不够细致导致的。重新生成第二周的知识地图，
> 要求对每个知识点都要有一句或者两句话的解释。后续根据知识地图矫正原文的时候，
> 原文必须符合解释的内容。」

#### 8.11.1 病灶：地图只有「名字」，没有「意思」

**旧写法（不合格）**：

```
├─ 一、行支（第二支 · 造作）
│   ├─ 行＝福行 · 非福行 · 不动行（共 29 种思）
│   └─ 三论点证「无业则无果报」
```

`三论点` 是哪三个？`福行/非福行/不动行` 各指什么？**地图里查不到。**
于是矫正原文时只能凭记忆猜——**地图失去了作为验收基准的功能**。

**新写法（合格）**：

```
├─ 一、行支（第二支 · 造作）
│   ├─ 行＝「造作」，即思心所驱使身、语、意去造业
│   │   · 福行＝善的造作（13 种思）；非福行＝不善的造作（12 种思）；
│   │     不动行＝色界无色界的禅定造作（4 种思）；三类共 29 种思
│   └─ 三论点证「无业则无果报」＝从「业」「果报」「作者」三个角度各推一遍，
│       证明没有独立的作者，果报只是业缘的相续
```

#### 8.11.2 释义的四条硬要求

| # | 要求 | 反例（不合格） |
|:--|:--|:--|
| 1 | **术语必释义**——巴利/论典术语须给中文白话解释 | `名色` 不说是「名＝受想行识，色＝四大与所造色」 |
| 2 | **判断句必展开**——「证…」「说…」「…故」须写出怎么证／说了什么 | `三论点证「无业则无果报」` 只写结论 |
| 3 | **数量词必列举**——「N 种／N 类／N 支」须列出或给归类依据 | `32 种世间果报识` 不列也不说怎么分 |
| 4 | **喻/例必点对应关系**——譬喻须写清「A 喻 B」 | `树鸟譬喻` 不写鸟＝什么、树＝什么 |

**篇幅弹性**：一句能说清的一句，需要两句的给两句。**不设上限，但每点不得少于一句。**

#### 8.11.3 ★双向约束：地图 ⟷ 原文 互为验收标准

| 方向 | 约束 | 违反后果 |
|:--|:--|:--|
| **地图 → 原文** | 原文必须**符合地图的释义内容**——地图说了什么，原文就得讲什么 | 原文缺该释义 → **判缺口，必须补** |
| **原文 → 地图** | 地图不得出现原文**无从支撑**的释义（凭空编造） | 地图写飞了 → 补不进去，地图须回改 |

**实操含义**：

- 覆盖矩阵的**判定关键词，应直接从地图释义里取**，不再从知识框架的粗条目里取。
- 只要**地图有释义、原文没有对应讲解落点，就是 ○ 或 ✗**，不再是「未定义」。
- 地图释义**同时是补写目标**：补写照地图释义写，写完逐句核对地图，**句句有落点才算补完**。

#### 8.11.4 作业顺序

1. 读 `知识框架与要点/读书会NN_…_知识框架与要点.md` 对应周次（4周版取「三、4周版 · 4WN」）。
2. 对每个知识点，**先从素材/`原文全集.md` 里找出它的解释**，找不到的标记「待考」。
3. 按 8.11.2 写释义；**释义须能溯源**，不得自创法义。
4. 写进 `## 🗺 本周知识地图` 节（紧跟信息卡之后、静心开场之前）。
5. **用新地图重跑覆盖矩阵**（关键词取自地图释义）→ 出缺口清单 → 补原文 → 复检。
6. 地图变更须留痕（「原地图 → 新地图 → 因此新增的缺口」）。

#### 8.11.5 与既有规则的关系

- **不替代** 第八节三维度验收，而是**强化其第①维（覆盖度）**——地图细了，覆盖矩阵才有准星。
- 结构规则（位置／来源／`📌 来源：` 标注）**继续有效**，本条是**在其之上追加「逐点释义」**。
- ⚠️ **地图不计入字数**（`count_spoken.py` 只算 `## 📖 共读原文N` 节），
  写细**不占朗读额度**，不必为省字数而压缩释义。
