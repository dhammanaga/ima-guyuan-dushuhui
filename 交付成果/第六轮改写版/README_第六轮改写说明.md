## 三、什么算"改写"（与第五轮精修的区别）

| 维度 | 第五轮精修（已完成） | 第六轮改写（进行中） |
| :--- | :--- | :--- |
| 底本 | 课件 OCR ＋ 录音转写，夹大量同音讹字 | **尊者提供的朗读稿，逐字照录** |
| 目标 | 结构合规、可朗读、字数达标 | 在此基础上**提升法义准确度与可读性** |
| 字数 | 共读每段 ≤3600 字（8周版 ≤4500） | **同一硬约束，不得超** |
| 环节 | 4周版 9 环节 / 120 分钟 | **不变**（环节结构与时长一律不动） |

**第六轮改写必须做到的三条底线：**

1. **逐字照录尊者提供的朗读稿**，一字不改、不压缩、不"顺手优化"。
2. **不丢知识要点**——术语、数字、引文、出处，一个不许丢。
3. **交付前三脚本必跑**（见下节）。

## 四、交付前三脚本（`_规范/脚本/`）

| 脚本 | 查什么 | 合格线 |

| `count_spoken.py <文件>` | 朗读字数 ＋ 知识地图节是否存在 | 4周版每段 ≤3600；8周版 ≤4500 |

## 五、改写时的三条铁律（沿用第五轮规范）

### 1. 绝不擅自改动尊者亲手写／改的内容

尊者亲手写、亲手改的文字，**一字不动**——不压缩、不删减、不调换顺序。
即使字数超标、时长装不下，也**只报告并请尊者裁定**，绝不自作主张处理。
我只做**结构层**的技术修复（标题层级、换行符、HTML 实体、EXT_READ 标记、时间戳），这些**不改变任何一个字**。

### 2. 第五轮是只读基准

对比 diff 一律指向 `交付成果/第五轮精简版/`。
**第五轮目录不再改动**——它是第六轮的参照系，改了就失去意义。

### 3. 推送走 GitHub REST API，绝不 git commit -a

本仓库索引残缺（约 5200 条假删除），`git add -A` / `git commit -a` 会**真删文件**。
一律用 `_规范/脚本/push_via_api.py`（单文件）或 Trees API（整目录），且推完须回读验证。

## 六、时间戳与交付格式

带版本标记的交付稿，**第1 行必须是右对齐 div**：

```html
<div align="right">📅 最近更新：YYYY-MM-DD HH:MM　|　版本标签</div>
```

第六轮的版本标签建议写作 `第6轮改写版`。

> ⚠️ **回向词全篇唯一、一字不改**（`愿我此功德，导向诸漏尽！…愿彼等一切，同得功德分！`），
> 主持人领读、全体合掌齐诵、照读不省。收尾只设一个环节，不得拆「收尾一／收尾二」。
