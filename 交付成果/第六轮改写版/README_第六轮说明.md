## 四、GitHub 上的创建方式（零复制）

本目录在 GitHub 上**不是**逐个文件下载再上传，而是用 git 的 tree 对象不可变性实现：

> **第五轮子树的 tree sha = `24d4c3099b…`**，直接把该 sha 挂到新路径 `交付成果/第六轮改写版`，
> 一次 Trees API 请求即可完成整棵子树的克隆——**零字节传输**，秒级完成。

因此 GitHub 上的 `第六轮改写版` 与本地工作副本**内容完全一致**（819 个原文件 + 2 份本轮新建说明 ＝ 821）。

## 五、改写时的规矩（沿用第五轮规范）

1. **第五轮是基准，只读不改。** 对比 diff 时请指向 `第五轮精简版`。
2. 交付前必跑三个脚本（路径 `_规范/脚本/`）：
   - `count_spoken.py <文件>` —— 朗读字数（4周版每段 ≤3600 字）
   - `final_check.py <文件>` —— 时间戳／换行符／EXT_READ 标记／回向词，五项必查
   - `check_format.py <文件>` —— 标题层级与格式
3. **回向词全篇唯一、一字不改**（`愿我此功德，导向诸漏尽！…愿彼等一切，同得功德分！`）。
4. 带时间戳的交付稿，第1 行必须是右对齐 div：`📅 最近更新：YYYY-MM-DD HH:MM　|　版本标签`。
5. 推送走 GitHub REST API（`push_via_api.py`），**绝不 `git commit -a` / `add -A`** —— 本仓库索引残缺，会真删文件。
