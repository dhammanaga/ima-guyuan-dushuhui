## 一、绝对红线（违反即作废）

1. **共读原文一字不改** —— 逐字照录，不改写、不缩写、不"润色"、不拼接、不虚构。
2. **学员版禁止手工编辑** —— 必须由脚本从主持人版派生。
3. **术语与数字一字不动** —— 仅可删减冗余句，不可改写术语、不可改数字。
4. **定界标记不许动** —— `、` 及其位置。
5. **绝覆盖原版本** —— 修订必另立目录/另存文件名。
6. **禁临时链接** —— 一律用「知识库出处＋media_id＋打开方式」，`https?://` 扫零。
7. **media_id 原样整串复制** —— 严禁手工拆分/拼接/重排（曾因手拼一字符整篇报废）。
8. **时长必封顶 120 分钟** —— 各环节之和 ≤120，超时是读书会最常见的致命伤。
9. **时区一律北京时间**。

## 二、字数规则（2026-10-12 尊者裁定·唯一算法）

### 2.1 硬线：时长 × 中等偏慢 180 字/分钟，**逐段独立判定**

| 版本 | 共读环节 | 时长 | **朗读字数上限** | 判定 |
|:--|:--|--:|--:|:--|
| **4 周版** | 共读原文1 | 20 min | **≤ 3600 字** | **独立判**，不相加 |
| **4 周版** | 共读原文2 | 20 min | **≤ 3600 字** | **独立判**，不相加 |
| **8 周版** | 共读 | 25 min | **3600–5400 汉字** | 单段判定：不足 3600 补足／超 5400 压缩 |

推导：20 × 180 = 3600（4 周版每段上限）；8 周版 25 min 理论量 4500，**2026-10-17 尊者令改为 3600–5400 纯汉字**。

### 2.2 ◈扩展段字数**不受限制**（2026-10-13 尊者令）

> 尊者原话（2026-10-13）：「**放宽字数限制，拓展内容字数不受限制。**」

- **★核心＝要念的**（控在 2.1 上限内）；**◈扩展＝时间富余才加读的，字数不限**。
- **旧令废止**：2026-10-12「扩展内容也不要多，不要超过5分钟字数」（≤900 字/节）**作废**。
- **工具判定**：`count_spoken.py` **只判全段 ≤3600**（8 周版 3600–5400 汉字），
  **不再对扩展段单独判超**，仅统计显示（形如 `扩展 1520(不限)`）。
- **仍须遵守**：扩展段不得跑题、不得重复，须来自知识地图释义落点，**不为凑量灌水**。

### 2.3 只算「要念出来」的量

**＝ 仅 `## 📖 共读原文N` 节内的可朗读文字。**

| 计入 | 不计入 |
|:--|:--|
| 材料正文段落（原文照录） | 整份文件总字符数（速览表/信息卡/讨论题/特别提醒/延伸阅读） |
| `**一、xxx**` 等段标题行本身 | `### 原文材料X：…` 材料标题行 |
| | `- **文件**：《…》` 行 |
| | `> ⚠️ 主持人操作：`、`> 主持人：` 行 |
| | `**主持人课前准备…**` 及其下 1./2./3. 编号清单 |
| | `---` 分隔行 |

### 2.4 双向字数令（尊者）

> 「字数限制要遵守，不足要补足（要符合知识框架和要点，不跑题不重复），超过要减少（不丢要点）。材料来源于知识库，也可以直接用原文全集里的内容。」

- **不足 = 缺口**：优先补「讲稿已引用、但没落到原文」的悬空段落；来源优先级 仓库内 `原文全集.md` > IMA 知识库。
- ⚠️ 补进来的正文仍受 ★/◈ 分级约束，**别把 ◈ 全提成 ★**。
- ⚠️ 补原文必须剔掉原文自带的层级标题行 `^#{1,6}\s`。

### 2.5 超限压缩优先序（不可颠倒）

**先删/压 ◈扩展段 → 再对 ★核心段做句内压缩**（去口头填充、去重复例证）。
★核心段的知识要点、术语、数字、经文引文**一个不许丢**。
删掉的整段要在该材料「⚠️主持人操作」行注明去向。

### 2.6 统计纪律

- 用 `len()`，**禁用 `wc -c`**（那是字节数）。
- 工具：`_规范/脚本/count_spoken.py`（已按新口径重写：逐段判「全段字数 + 扩展字数」，并自检知识地图节）。
  ```
  python3 _规范/脚本/count_spoken.py <文件.md>…      # 逐段报并判合规
  python3 _规范/脚本/count_spoken.py -v <文件.md>     # 逐段明细
  python3 _规范/脚本/count_spoken.py<目录>/          # 批量扫，末尾汇总
  ```
  输出形如 `共读原文1=3385/3600(扩868)  合规`。
- **交付前必跑**，压到 `✓ 合规` 才许 commit。

## 二十二、★ 交付前三维度验收（2026-10-13 尊者令 · 全文见 RULES5 第八节）

> 本清单为**镜像条目**。完整规则、判定表、验收清单以 **`第5版精修规则_RULES5.md` 第八节**为准；
> 若两处表述不一致，**改本节，不改 RULES5 第八节**（依21.1 优先级顺序）。

### 22.1 一句话

**光跑 `count_spoken.py` 拿到 ✓ 合规，不等于交付合格。**
它只查结构与字数，**查不出漏了什么、讲清了没有**。三维度验收是交付前最后一关，每周必做。

### 22.2 三维度

| 维度 | 回答 | 判定物 |
|:--|:--|:--|
| ① 覆盖度 | 知识点**有没有** | 覆盖矩阵（原子级） |
| ② 篇幅配比 | **给了多少**字 | 散点图（复杂度 × 实际字数） |
| ③ 要素槽位 | 提到 ≠ **讲清楚** | 槽位检查表（6 槽，记 n/6） |

⚠️ **必须交叉验证。** 单维度只能得半截结论（实测：篇幅超标 888 字与观察方法整块缺失是同一病因）。

### 22.3 四条最容易违反的（实测教训）

1. **拆到原子级**——一条要点含 4–8 个原子点，命中任一即整条判「完整」＝ **系统性高估**。
   实测：粗判 12/12=100%，原子级实为 **24/35=68.6%**，差 31 个百分点。
2. **判定域＝讲解本体**（共读原文1＋共读原文2）。**本周知识地图节、信息卡、延伸阅读一律不计入**——
   它们只提示「有」，是导航性提及，会把覆盖率虚高（实测 `藤`／`八处`／`四圣谛` 讲解本体 0 命中）。
3. **⚠️ 关键词计数 0 命中 ≠ 缺失，必须回原文核对异写。**
   实测反例：`因漏集起故` 检索 0 命中，实为异写 `因漏[āsava]集起故`，引文在。
   直接采信会**凭空造出不存在的缺口**。异写形态：巴利术语方括号／新旧译并列／转写重复。
4. **「○」档最易漏判**——素材散在多处但**未串成完整判断句**时，应判○（部分覆盖），
   不是 ●。判断句是否落地是 ○与 ● 的分界。

### 22.4 字数腾挪：合法顺序 + 上限

⚠️ **`count_spoken.py` 上限：全段 ≤3600**（8 周版 3600–5400 汉字）。
**◈扩展段字数不受限制**（2026-10-13 尊者令）——扩展内容可自由增补，**不必再为扩展段腾字数**。
但**全段上限仍须遵守**（核心＋扩展之和 ≤3600）；若全段超限，新增内容仍须在同段内腾挪。

**新增内容必须先在同段内腾挪，顺序不可颠倒：**

1. **转写重复段**（去重复，不丢要点，首选）
2. **原译**（若主持人操作行已授权「可只读新译、带过原译」；删前核实新译完整含关键引文）
3. **★核心句内压缩**（术语与数字一字不许动）

**绝不删**：术语与数字 · 关键引文与出处 · ★核心照录要点
（压无可压时按RULES5 2.5 第4 条整段不入正文、操作行注明去向）

## 二十三、★★ 知识地图必须逐点带释义（2026-10-13 尊者令 · 全文见 RULES5 8.11）

### 23.1 尊者原话

> 「你的问题是知识地图不够细致导致的。重新生成第二周的知识地图，
> 要求对每个知识点都要有一句或者两句话的解释。后续根据知识地图矫正原文的时候，
> **原文必须符合解释的内容**。」

### 23.2 一句话

**地图是验收基准，基准必须自带释义。**
名字级的地图只能查出「有没有」，**释义级的地图才查得出「讲没讲清」**。

### 23.3 旧 vs 新

```
旧（不合格，只有名字）：
├─ 行＝福行 · 非福行 · 不动行（共 29 种思）
└─ 三论点证「无业则无果报」

新（合格，逐点带释义）：
├─ 行＝「造作」，即思心所驱使身、语、意去造业
│   · 福行＝善的造作（13 思）；非福行＝不善的造作（12 思）；
│     不动行＝色界无色界的禅定造作（4 思）；三类共 29 种思
└─ 三论点证「无业则无果报」＝从「业」「果报」「作者」三个角度各推一遍，
   证明没有独立的作者，果报只是业缘的相续
```

### 23.4 四条硬要求

| # | 要求 |
|:--|:--|
| 1 | **术语必释义**——巴利/论典术语给中文白话解释 |
| 2 | **判断句必展开**——「证…」「说…」「…故」写出怎么证／说了什么 |
| 3 | **数量词必列举**——「N 种／N 类」列出或给归类依据 |
| 4 | **喻/例必点对应关系**——写清「A 喻 B」 |

**篇幅弹性**：一句能说清的一句，需要两句的给两句；**每点不得少于一句**。

### 23.5 ★双向约束（本条核心）

| 方向 | 约束 | 违反后果 |
|:--|:--|:--|
| 地图 → 原文 | 原文必须**符合地图的释义内容** | 原文缺该释义 → **判缺口，必须补** |
| 原文 → 地图 | 地图不得有原文**无从支撑**的释义 | 地图写飞了 → 补不进去，地图须回改 |

**实操**：
- 覆盖矩阵的**判定关键词改从地图释义里取**，不再从粗框架条目取。
- **地图有释义、原文无落点 → 直接判 ○ 或 ✗**，不再是「未定义」。
- 地图释义**同时是补写目标**，补完逐句核对地图，**句句有落点才算补完**。

### 23.6 作业顺序

1. 读知识框架对应周次 → 2. **先从素材/`原文全集.md` 找出每个知识点的解释**（找不到标「待考」）
→ 3. 按 23.4 写释义（**须可溯源，不得自创法义**）→ 4. 写入 `## 🗺 本周知识地图`
→ 5. **用新地图重跑覆盖矩阵**（关键词取自地图释义）→ 补原文 → 复检
→ 6. 地图变更留痕（原地图 → 新地图 → 新增缺口）。

### 23.7 两个易错点

- ⚠️ **不替代**第二十二节三维度验收，而是**强化其第①维（覆盖度）**。
- ⚠️ **地图不计入朗读字数**（`count_spoken.py` 只算 `## 📖 共读原文N`），
  写细**不占朗读额度**，不必为省字数压缩释义。

| :--- | :--- |

### 24.8 第六轮的技术坑（本轮实际踩到，务必先看）

**坑一：写回时行尾残留 `\r` → 变成 `\r\r\n`（实测 305 处）**

```python
# ❌ 错：L 已按 "\n" split 成行、join 回字符串后，每行尾还带着 "\r"，
#       再 replace("\n", "\r\n") 就变成 "\r\r\n"
out = L.replace("\n", "\r\n")

# ✅ 对：先逐行去掉残留 \r，再统一替换换行符
body = "\n".join(l.rstrip("\r") for l in L.split("\n"))
out = body.replace("\n", "\r\n") if crlf else body
# 写盘后必须断言
assert out.count("\r\r\n") == 0
```

**坑二：GitHub token 取错段 → 401 Bad Credentials**

`~/.git-credentials` 行格式是 `https://<user>:<token>@github.com`：

```python
# ❌ 错：split("@")[-1] 取到的是域名段
tok = ln.split("://")[-1].split("@")[-1].split(":")[-1]

# ✅ 对
tok = ln.split("://", 1)[1].split("@", 1)[0].split(":", 1)[1]
```

**坑三：切片替换共读节，边界必须取「紧随其后的下一个环节标题」**

共读1 的终点是 `## 💬 第一轮分享`，共读2 的终点是 `## 💬 第二轮分享`。
**绝不可跨到下一节标题**（如用 `## 📖 共读原文2` 或 `## 🎯 第二轮主题讨论` 作终点），
否则中间的环节整节被替换删除。替换后必须逐个 `assert` 环节标题仍在。

**坑四：行尾 `\r` 会让字符串相等断言全部误判**

原文按 `"\n"` split 后每行尾仍带 `\r`。`startswith()` 定位不受影响，
但 **`==` / `in` 断言会全数失败**，症状是「明明在列表里却说环节丢失」。
正解：`L = [l.rstrip("\r") for l in raw.decode("utf-8").split("\n")]` 归一后再比。

**坑五：写脚本时两个三引号块写成一个（变量未定义）**

`NEW_RO1`／`NEW_RO2` 易合并。**写完先自查**：
`grep -n 'NEW_RO1 = \|NEW_RO2 = \|^+ up\|^+ dn' 脚本.py`，数一遍变量与拼接点，再运行。

**坑六：环节标题粘连会制造「假超限」⭐**

`## 🧘 静心开场` 或 `## 💬 第二轮分享` 被吸进上一行末时，
**该节内容会被算进相邻共读节的朗读字数**，造成假超标。
实测 18W2：修前 4196（超 596）／修后 3441；18W3：修前 3957（超 357）／修后 3237；
18W4：修前 3966（超 366）／修后 3491。
⇒ **遇到共读超限，先查有无环节标题粘连，再谈压缩。**

**坑七：`r"""` 三引号与 `\U` 转义（脚本自身）**

含 Windows 路径的 Python 三引号串**必须用 `r"""` 开头**，否则 `\Users\27659` 被当 `\U` 转义报错；
代价是要在拼接时把字面 `\n` 还原成真换行 —— 而**全局 `.replace("\\n","\n")` 会连代码块里的
`\n` 一起还原，把文档中的代码示例撑散**。故还原后**必须回读检查代码块是否完好**。
